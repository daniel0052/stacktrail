## Objetivos de aprendizagem

Explique lista, busca linear, contagem e ordenação; compare crescimento de trabalho e memória sem depender de matemática avançada.

## Antes de começar

Conheça laços, índices, tabelas de frequência e teste de mesa. Complexidade aqui descreve crescimento, não cronômetro.

## Organizar muda o trabalho

Uma pilha de livros sem ordem exige olhar vários títulos para encontrar um. Uma estante ordenada permite eliminar regiões ao comparar títulos. Ordenar custa trabalho, por isso a melhor escolha depende de quantas buscas serão feitas e de como a coleção muda.

Uma lista/array mantém elementos em posições. Nesta etapa, índices começam em zero: `[8, 3, 8]` tem tamanho três e último índice dois. Repetição é permitida, a menos que o contrato a proíba.

## Busca linear

```text
PARA índice DE 0 ATÉ tamanho − 1
  SE lista[índice] = alvo
    DEVOLVER índice
  FIM
FIM
DEVOLVER -1
```

Percorremos na ordem e devolvemos a primeira ocorrência. Se o alvo estiver ausente, examinamos todos os elementos. Lista vazia faz zero comparações. Com n elementos, o pior caso cresce proporcionalmente a n: chamamos isso de O(n). A busca não cria outra lista, então usa espaço extra constante, O(1), além da entrada.

## Busca binária: um pré-requisito importante

Em uma lista ordenada, compare o alvo com o elemento do meio. Se for maior, descarte a metade inferior; se for menor, descarte a superior. Cada passo reduz aproximadamente à metade os candidatos. Para oito elementos, restam aproximadamente quatro, dois e um.

Esse crescimento é O(log n), na busca isolada. Verificar se a entrada está ordenada exige percorrê-la, O(n). Ordenar uma lista só para uma busca pode custar mais que usar a linear. Não diga que uma estratégia é sempre melhor sem incluir preparação e contexto.

## Ordenação por seleção

Uma abordagem simples encontra o menor elemento da região ainda não ordenada e o coloca na próxima posição. Repete o processo na região restante.

| Passo | Lista | Região ainda não ordenada |
| --- | --- | --- |
| Inicial | 4, 2, 3 | Todos |
| Selecionar menor | 2, 4, 3 | Índices 1 e 2 |
| Selecionar próximo | 2, 3, 4 | Índice 2 |

Procurar o menor repetidamente faz cerca de n × n comparações em escala de crescimento: O(n²). Não é uma recomendação de implementação para grandes dados; é um exemplo para entender o custo. Algoritmos de ordenação melhores têm outros contratos e trade-offs.

## Contagem e memória

Uma tabela de frequências guarda um contador por valor distinto. Se há k valores distintos, precisamos de O(k) espaço adicional. Ler n itens continua exigindo n visitas; o custo das operações da tabela depende da estrutura concreta, e não deve ser declarado como garantia universal de uma API.

JavaScript tem arrays; TypeScript pode descrevê-los como `number[]`. Na implementação, atenção: o `sort()` padrão de JavaScript ordena por representações textuais e modifica o array. Para números, é necessário um comparador adequado. Esse detalhe técnico foi conferido na documentação MDN; o pseudocódigo não depende dessa API.

## Erros comuns

- Confundir O(n) com “n milissegundos”: é crescimento, não medição.
- Usar busca binária em lista desordenada: descarte deixa de ser justificado.
- Esquecer memória extra: copiar uma lista exige espaço proporcional ao tamanho.
