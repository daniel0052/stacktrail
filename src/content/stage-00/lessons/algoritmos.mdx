## Objetivos de aprendizagem

Descreva uma solução finita usando sequência, decisão e repetição; explique o significado de cada variável e a condição de parada.

## Antes de começar

Saiba interpretar entradas e saídas, decompor e registrar hipóteses. Pseudocódigo não exige linguagem específica.

## Uma receita suficientemente precisa

“Mexa até ficar bom” depende de julgamento não definido. “Misture durante dois minutos” tem uma condição verificável. Um algoritmo precisa de passos definidos e uma forma de terminar, para as entradas do seu contrato. Nem toda instrução cotidiana é um algoritmo suficientemente preciso.

Pseudocódigo é uma descrição estruturada do raciocínio. Não existe uma sintaxe universal obrigatória. Nesta etapa, usamos `←` para atribuição, `SE` para decisão e `PARA CADA` para percorrer uma lista finita. Indentação indica o que pertence a cada bloco.

## Sequência, decisão e repetição

| Estrutura | Ideia | Exemplo cotidiano |
| --- | --- | --- |
| Sequência | Um passo acontece após outro | Separar ingredientes antes de misturar |
| Decisão | A regra escolhe um caminho | Se há alergia, não usar aquele ingrediente |
| Repetição | Aplicar passos a vários elementos | Preparar uma porção para cada pessoa |

Um contador guarda “quantos”; um acumulador guarda uma combinação como soma. Inicializar não é detalhe: sem um estado inicial, a primeira atualização não tem significado.

## Exemplo: somar durações válidas

Contrato: recebemos uma lista de durações inteiras entre 1 e 120 minutos. Queremos a soma, ou “dados inválidos” se qualquer duração não cumprir a regra. Lista vazia produz zero.

```text
total ← 0
PARA CADA duração EM durações
  SE duração não é inteiro OU duração < 1 OU duração > 120
    DEVOLVER "dados inválidos"
  FIM
  total ← total + duração
FIM
DEVOLVER total
```

`total` começa em zero porque ainda não processamos nenhuma duração. Após cada passo válido, representa a soma de tudo o que já foi processado. A repetição termina porque a lista é finita e cada elemento é visitado uma vez. A validação vem antes da soma.

Para `[20, 15]`, total passa de 0 para 20 e depois 35. Para `[20, 0]`, o resultado é erro, não 20: a especificação rejeita toda a lista, em vez de ignorar valores inválidos.

## Uma repetição controlada por condição

```text
índice ← 0
ENQUANTO índice < tamanho da lista
  examinar lista[índice]
  índice ← índice + 1
FIM
```

Sem incrementar o índice, a condição pode nunca mudar. Se começar em zero, os índices válidos vão até tamanho menos um; usar `≤ tamanho` tentaria visitar uma posição inexistente. Não misture contagem de elementos e último índice.

## Erros comuns

- Usar uma variável antes de inicializar: escreva o estado inicial.
- Confundir atribuição com comparação: `total ← 0` altera; `total = 0?` pergunta.
- Laço sem progresso: identifique o que se aproxima da condição de parada.
- “Validar entrada” sem definir validade: substitua por condições concretas.

## Miniatividade

Escreva um algoritmo para contar durações maiores que 30 na lista `[10, 40, 30, 50]`. Defina o resultado de lista vazia e de valor inválido. Trace o contador após cada elemento; não entregue apenas o total final.

## Resumo e revisão

Pseudocódigo comunica decisões sem depender de sintaxe. Sequências ordenam, decisões separam casos e repetições processam coleções. Estado inicial e término fazem parte da correção.
